# Deterministic demo data

Build the local reviewer demo from inspectable sources:

```bash
.venv/bin/python examples/build_demo.py --db-path demo.sqlite3 --force
finance-tracker web --db-path demo.sqlite3
```

The builder uses only public services and creates, in order:

- seven accounts and their read-only opening activities;
- five category aliases;
- 277 account-assigned income/expense rows from `sample_activities.csv`;
- eight realistic savings, investment, loan, and card-payment transfers;
- four recurring templates and four July entries, followed by a duplicate-safe second apply;
- 820 dated adjustment entries that provide observed month-end balances and investment/interest
  changes across a ten-year net-worth history;
- 120 budgets from `sample_budgets.csv`;
- one historical account adjusted to zero and archived.

The result is 1,116 activities. July 2026 contains 25 cashflow entries with income of `$4,500.00`,
expenses of `$3,843.53`, and net savings of `$656.47`. As of 2026-07-16 the demo has assets of
`$64,865.00`, liabilities of `$8,585.00`, and net worth of `$56,280.00`.

Previewing the source against the built ledger reports all 277 source activities as duplicates:

```bash
finance-tracker activity import examples/sample_activities.csv --preview \
  --db-path demo.sqlite3
```

Export the complete semantic activity format with:

```bash
finance-tracker activity export exports/activities.csv --db-path demo.sqlite3
finance-tracker budget export exports/budgets.csv --db-path demo.sqlite3
```

The source activity header is:

```text
kind,amount,category,description,date,account,from_account,to_account
```

Opening entries are deliberately absent because account creation owns them. Adjustments and
transfers are generated by the builder so their intent remains easy to review in code.
